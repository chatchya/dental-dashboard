# Zentr Dental — Admin UI Prototype

ต้นแบบหน้าจอระบบหลังบ้านสำหรับคลินิกทันตกรรม ของแพลตฟอร์ม **Zentr** โดย Arise Corporation

เป็น static HTML ล้วน ไม่มี build step ไม่มี dependency เปิดไฟล์ในเบราว์เซอร์ได้ทันที

## หน้าจอในระบบ

| ไฟล์ | หน้าจอ | ความสามารถ |
|---|---|---|
| `index.html` | ภาพรวม | KPI, ตารางวันนี้, แผนรักษารอตอบรับ, กล่องข้อความรวม, งานแล็บ, recall 6 เดือน |
| `schedule.html` | ตารางนัดหมาย | มุมมองวัน/สัปดาห์/เดือน, แยกตามเก้าอี้หรือทันตแพทย์, เพิ่ม–แก้ไข–ลบนัด, ตรวจจับการจองทับ, หาเวลาว่างถัดไป |
| `queue.html` | คิววันนี้ | กระดานคิวเรียลไทม์ 5 สถานะ, ลากวาง, เรียกคิวถัดไป, เพิ่ม walk-in, จับเวลารอ |
| `patients.html` | ข้อมูลคนไข้ | ทะเบียนคนไข้, แผนภูมิฟัน FDI 32 ซี่, ประวัติการรักษา, เพิ่ม–แก้ไข–ลบ |
| `ortho.html` | ข้อมูลการจัดฟัน | ขั้นการรักษา, รอบปรับเครื่องมือ, ตารางงวดผ่อน, รับชำระรายงวด |
| `treatment-plans.html` | แผนการรักษาและแพ็กเกจ | แพ็กเกจที่เปิดขาย, คนไข้จัดฟัน, ยอดค้างรับและรายได้รอรับรู้ |
| `lab.html` | งานแล็บ | ติดตามชิ้นงาน, เตือนเวลากันชนก่อนวันนัดใส่, ส่งแก้งาน, ผลงานของแล็บแต่ละเจ้า |
| `payments.html` | การชำระเงิน | บิล/ใบเสร็จ, รับชำระบางส่วน, ช่องทางรับเงิน, ตารางอายุหนี้ |

## ระบบดีไซน์

- **ฟอนต์** IBM Plex Sans Thai (เนื้อหา) + IBM Plex Mono (ตัวเลขและ label)
- **สีหลัก** petrol ink `#06232C` / brand blue `#2E6BE6` / aqua `#38C6DC`
- ทุกไอคอนและกราฟเป็น inline SVG เขียนเอง ไม่มี icon font หรือ chart library
- Responsive ถึงจอมือถือ และรองรับ `prefers-reduced-motion`

## การพัฒนา

ไม่ต้องติดตั้งอะไร เปิดไฟล์ตรง ๆ หรือรัน static server:

```bash
python3 -m http.server 8080
# เปิด http://localhost:8080
```

## ทดสอบ

หน้าที่มี interaction ถูกทดสอบด้วย jsdom รวม 198 เคส ครอบคลุมการเดินสถานะ,
การตรวจจับการจองทับ, การคำนวณยอดเงิน และการเลิกทำ (undo) ทุกการกระทำ

## สิ่งที่ยังไม่มีในต้นแบบนี้

ข้อมูลทั้งหมดอยู่ในหน่วยความจำของเบราว์เซอร์ รีเฟรชแล้วกลับค่าเริ่มต้น
ก่อนนำไปใช้จริงต้องเพิ่ม:

- **API และฐานข้อมูล** — ตรรกะกันจองทับเก้าอี้/ทันตแพทย์ต้องย้ายไปเป็น constraint ที่ฝั่ง server
  เพราะการตรวจฝั่ง client ป้องกัน race condition ไม่ได้
- **Realtime sync** — หน้าคิวต้องใช้ WebSocket หรือ SSE เพราะเคาน์เตอร์ ผู้ช่วย และห้องแพทย์ดูพร้อมกัน
- **Audit log** — ทุกการแก้ไขบิลและการรับชำระต้องบันทึกว่าใครทำเมื่อไหร่ และลบไม่ได้
  ปุ่มยกเลิกบิลควรเป็น void ที่ยังเห็นรายการเดิม ไม่ใช่ซ่อนออกจากตาราง
- **PDPA** — ข้อมูลสุขภาพเป็นข้อมูลอ่อนไหวตามมาตรา 26 ต้องมีฐานความยินยอมโดยชัดแจ้ง
  และมาตรการรักษาความปลอดภัยที่เข้มกว่าข้อมูลทั่วไป ควรออกแบบตั้งแต่ schema
- **สิทธิ์ผู้ใช้** — แยกบทบาทเคาน์เตอร์ / ผู้ช่วย / ทันตแพทย์ / เจ้าของคลินิก
